# DFD Secrets

These YAML files are **templates** showing the required secrets and their keys.
They are NOT managed by kustomize or ArgoCD — secrets must be created manually
in the target namespace before deploying the application.

## Required secrets

All secrets must be created in the DFD namespace (e.g. `dfd`).

### dfd-database

PostgreSQL connection credentials.

```bash
oc -n dfd create secret generic dfd-database \
  --from-literal=username=dfd \
  --from-literal=password='<your-password>' \
  --from-literal=database=dfd \
  --from-literal=url='postgresql://dfd:<your-password>@dfd-postgresql:5432/dfd'
```

### dfd-kubearchive

KubeArchive API access for fetching pipeline run data.

```bash
oc -n dfd create secret generic dfd-kubearchive \
  --from-literal=base-url='https://kubearchive.<your-cluster>' \
  --from-literal=token='sha256~<your-token>'
```

### dfd-vertex-ai

Google Cloud Vertex AI configuration for Claude API access.

```bash
oc -n dfd create secret generic dfd-vertex-ai \
  --from-literal=project-id='<your-gcp-project>' \
  --from-literal=region='us-east5'
```

### dfd-gcp-credentials

GCP service account key file (mounted as a volume).

```bash
oc -n dfd create secret generic dfd-gcp-credentials \
  --from-file=credentials.json='<path-to-service-account-key.json>'
```

### dfd-aws-credentials

AWS IAM credentials for S3 access.

```bash
oc -n dfd create secret generic dfd-aws-credentials \
  --from-literal=access-key-id='<your-access-key>' \
  --from-literal=secret-access-key='<your-secret-key>'
```

### dfd-aws-s3

S3 bucket configuration.

```bash
oc -n dfd create secret generic dfd-aws-s3 \
  --from-literal=bucket='<your-bucket-name>' \
  --from-literal=region='us-east-1'
```

### dfd-oauth-proxy-cookie

Cookie encryption secret for the OAuth proxy sidecar.

```bash
oc -n dfd create secret generic dfd-oauth-proxy-cookie \
  --from-literal=cookie-secret="$(openssl rand -base64 32)"
```

### dfd-api-tls

This secret is auto-generated by OpenShift via the
`service.beta.openshift.io/serving-cert-secret-name` annotation on the
`dfd-api` Service. No manual creation needed.
